# Agent Spec: ClaimPulse — Autonomous Insurance Claim & Emergency Roadside Triage System

## Overview
**ClaimPulse** is an enterprise-grade, distributed multi-agent insurance claim intake, coverage verification, and 3-tier severity triage system built with the **Google Agent Development Kit (ADK)** for the **Gemini Enterprise Agent Platform (GEAP)**.

It implements a distributed **Supervisor + 3 Specialist Agents** architecture where each agent (`claimpulse-supervisor`, `claimpulse-intake-agent`, `claimpulse-triage-agent`, and `claimpulse-dispatch-agent`) is deployed as an independent **Reasoning Engine on Vertex AI Agent Runtime** and auto-registered in **Google Cloud Agent Registry**.

At runtime, the **Supervisor Agent** dynamically queries the project's **Agent Registry / Vertex AI Reasoning Engines API** (filtered by labels `app=claimpulse,role=specialist`), discovers which specialist agents are available, retrieves their **A2A (Agent-to-Agent) Agent Cards** over the Agent Runtime `/api/a2a/...` passthrough, and delegates work to them via `RemoteA2aAgent` (with automatic local in-process fallback when `CLAIM_PULSE_DEPLOYMENT_MODE=local` for offline CI/CD and `pytest` execution).

Furthermore, ClaimPulse enforces a **Deterministic A2UI v0.8 Presentation Engine** invariant: the LLM only classifies intent, routes tasks, and invokes typed Pydantic tools—it never generates raw HTML or JavaScript. Declarative A2UI v0.8 views (`Tabs`, `Slider`, `DateTimeInput`, `CheckBox`, `MultipleChoice`, `Card`) are built by typed Python builders and validated against the A2UI v0.8 catalog schema before transmission.

## Language
`python` (Python 3.11+, managed via `uv`, built on `google-adk[a2a,gcp,otel-gcp]`).

## Architecture & Sub-Agents
1. **`claimpulse-supervisor` (Root Orchestrator & Dynamic Discovery Router — Agent Runtime)**
   - Queries `AgentRegistryDiscoveryService` (`aiplatform.googleapis.com` / `agentregistry.googleapis.com`) to dynamically discover active remote specialist Reasoning Engines and bind them via `RemoteA2aAgent`.
   - Applies strategic model routing (`ModelRouter`: Gemini Flash for low-latency routing/intake, Gemini Pro for complex multi-vehicle/structural liability triage).
   - Enforces runner-wide safety guardrails, PII scrubbing callbacks, and context compaction.
2. **`claimpulse-intake-agent` (Policy & Identity Verification Specialist — Agent Runtime)**
   - Verifies policyholder identity, active policy coverage, deductible, and coverage inclusions/exclusions from the remote database.
   - Records structured FNOL (First Notice of Loss) intake records.
3. **`claimpulse-triage-agent` (3-Tier Severity & Coverage Assessor — Agent Runtime)**
   - Evaluates incident description, damage severity score (1–10 scale), vehicle/property drivable status, third-party involvement, and injuries to classify the claim into one of 3 deterministic tiers:
     - **Tier 1 — Fast-Track Self-Service (Severity 1–3, Minor Cosmetic / Glass Damage):** Instant digital payout calculation or express glass/dent repair voucher + certified workshop directory.
     - **Tier 2 — Adjuster & Certified Workshop Inspection (Severity 4–7, Moderate Collision / Property Damage):** Assigns a licensed senior claims adjuster, reserves a certified repair shop bay, and generates 1-click Google Calendar & Google Meet virtual inspection links.
     - **Tier 3 — Critical Emergency & Roadside Dispatch (Severity 8–10, Non-Drivable / Injuries / Hazard / Total Loss):** Immediate tow truck & roadside emergency dispatch, emergency hotline/911 escalation protocol, and live emergency adjuster Google Meet bridge.
4. **`claimpulse-dispatch-agent` (Roadside Dispatch, Adjuster & Workspace Scheduler — Agent Runtime)**
   - Dispatches emergency tow trucks / roadside assistance units, books certified adjuster appointments, and generates Google Calendar synchronization links and Google Meet virtual inspection rooms.

### Scope & Phasing
- **Phase 1 (Core Build — This Repository):** Complete end-to-end implementation of the 4-agent distributed architecture (`supervisor`, `intake`, `triage`, `dispatch`), Dynamic Agent Runtime Discovery (`AgentRegistryDiscoveryService`), dual remote/local storage (`FirestoreRepository` + `SQLiteRepository` with initial seed data), `HistoryCompactor` & `AsyncMemoryConsolidator`, `PIIScrubber` + OpenTelemetry tracing, A2UI v0.8 declarative builders & schema validator, Terraform IaC (`infra/` for Firestore, IAM, Secret Manager, and 4 Vertex AI Agent Runtime Reasoning Engines), GitHub Actions CI/CD, and comprehensive `pytest` + ADK evaluation suites.
- **Future Phases:** Live third-party telematics IoT crash sensor webhook ingestion via Pub/Sub ambient triggers and live satellite imagery damage estimation.

## Data Sources & Auth
- **Primary Remote Storage (Serverless GCP):** **Google Cloud Firestore (Native Mode)** accessed via `google-cloud-firestore` using Application Default Credentials (IAM service account `app_sa` with `roles/datastore.user`). Zero VPC/PSC networking overhead from Agent Runtime containers and \$0 idle cost.
- **Local / SQL Storage Adapter (Offline CI & Evaluator Compatibility):** Built-in **SQLite / Cloud SQL PostgreSQL** repository (`storage/database.py`) implementing the exact same repository protocol (`ClaimPulseRepository`), pre-seeded with realistic insurance policies, policyholders, accredited claims adjusters, certified repair workshops, and roadside tow units. Automatically selected when `CLAIM_PULSE_STORAGE_BACKEND=sqlite` (default in `pytest`).
- **Session & Cross-Session Memory:**
  - Managed **`VertexAiSessionService`** and **Vertex AI Memory Bank** (`PreloadMemoryTool` + `after_agent_callback`) when running on Agent Runtime.
  - **`HistoryCompactor`** (sliding-window token/turn compaction) and **`AsyncMemoryConsolidator`** (background extraction of policyholder facts, vehicle VINs/plates, and claim history).
- **Agent-to-Agent Auth:** Google Cloud IAM / OIDC identity tokens (`google.auth`) over Agent Runtime `/api/a2a/...` endpoints.

## Example Use Cases
1. **Use Case 1 — Tier 1 Minor Cosmetic Claim (Fast-Track):**
   - *Input:* `"Hola, soy titular de la póliza POL-CL-1001. Ayer estacionando tuve un rayón leve en el parachoques trasero, severidad 2/10, sin heridos y el auto anda perfecto."`
   - *Expected Output:* Supervisor delegates to Intake (`verify_policy`) and Triage (`assess_claim_severity`). Classifies as **Tier 1 (Fast-Track Self-Service)**, calculates net fast-track settlement vs. deductible, lists certified express body shops, and emits a validated A2UI v0.8 Fast-Track Resolution Card.
2. **Use Case 2 — Tier 2 Moderate Collision with Adjuster Scheduling:**
   - *Input:* `"Tengo la póliza POL-CL-1002. Choqué en un cruce a baja velocidad, el faro delantero y el capó quedaron abollados (severidad 6/10). No hay heridos pero necesito perito y taller."`
   - *Expected Output:* Classifies as **Tier 2 (Adjuster Inspection)**, matches a senior collision adjuster, schedules an inspection slot with a 1-click Google Calendar URL and Google Meet link for virtual pre-inspection, and emits a validated A2UI v0.8 Appointment & Adjuster Card.
3. **Use Case 3 — Tier 3 Critical Highway Emergency & Roadside Dispatch:**
   - *Input:* `"¡Ayuda! Póliza POL-CL-1003, sufrí un choque fuerte en la autopista Ruta 5 Sur km 42, severidad 9/10, salió humo del motor, el auto no enciende y estamos atrapados en la berma."`
   - *Expected Output:* Classifies as **Tier 3 (Critical Emergency)**, immediately invokes `dispatch_roadside_assistance` (assigning nearest tow/emergency unit with ETA), surfaces emergency safety instructions (911 / Autopista Emergency 133/131), opens an immediate on-call emergency adjuster Meet bridge, and emits a validated A2UI v0.8 Emergency Alert Card.
4. **Use Case 4 — Dynamic Agent Discovery & Registry Inspection:**
   - *Input:* `"¿Qué agentes especialistas están activos y registrados en el sistema para atender mi siniestro?"`
   - *Expected Output:* Calls `discover_available_specialists`, returning the live roster of discovered Agent Runtime specialists (`intake`, `triage`, `dispatch`), their endpoints, health status, and capabilities.

## Tools Required
1. **`discover_available_specialists(capability_filter: str)`**
   - *Purpose:* Queries `AgentRegistryDiscoveryService` (Vertex AI Reasoning Engines / Agent Registry API with local fallback) to discover active specialist agents, their A2A Agent Card URLs, and health status.
2. **`verify_policy_and_coverage(policy_number: str, incident_type: str)`**
   - *Purpose:* Looks up policyholder profile, vehicle/property details, coverage limits, deductible, and active status in Firestore/SQLite; stores verified policy context in `tool_context.state`.
3. **`assess_claim_severity(policy_number: str, symptom_or_damage_description: str, severity_score: int, is_drivable: bool, has_injuries: bool, location: str)`**
   - *Purpose:* Executes Pydantic-validated 3-Tier triage logic (`TIER_1_FAST_TRACK`, `TIER_2_ADJUSTER_INSPECTION`, `TIER_3_CRITICAL_EMERGENCY`), calculates estimated reserve/deductible impact, and persists the FNOL claim record.
4. **`schedule_adjuster_and_workshop(claim_id: str, specialty: str, preferred_date: str, modality: str)`**
   - *Purpose:* Matches an accredited insurance adjuster and certified repair workshop, creates the appointment in Firestore/SQLite, and generates a Google Calendar event link and Google Meet room URL.
5. **`dispatch_roadside_assistance(claim_id: str, location: str, hazard_level: str, requires_ambulance: bool)`**
   - *Purpose:* Dispatches an emergency tow truck / roadside response unit, records dispatch telemetry, and returns live unit ID, ETA, emergency safety protocol, and on-call adjuster Meet bridge.
6. **`get_claim_status_and_history(policy_number: str)`**
   - *Purpose:* Retrieves active claims, compacted session memory, and past claim history for the policyholder.

## Constraints & Safety Rules
1. **Strict UI Invariant (No LLM-Generated HTML/JS):** The LLM must never output raw HTML, `<script>` tags, or unvalidated UI components. All A2UI v0.8 payloads are generated deterministically by typed Python builders (`a2ui/components.py`, `a2ui/views.py`) and verified by `A2UICatalogValidator`.
2. **Active PII & Financial Scrubbing (`PIIScrubber`):** All logs, OpenTelemetry span attributes, and persisted trace payloads must pass through `PIIScrubber` to redact National IDs (RUT/SSN/DNI), license plates, VINs, credit card/bank account numbers, phone numbers, and email addresses.
3. **Life-Safety First Escalation Rule:** Whenever `has_injuries=True` or `severity_score >= 8` (fire, smoke, highway stranding, bodily injury), the agent MUST prioritize Tier 3 emergency instructions (911 / emergency services) and immediate roadside dispatch before asking administrative follow-up questions.
4. **Input Guardrails (`before_model_callback` & `before_tool_callback`):** Prompt injection attempts, malformed severity scores outside `1..10`, or unauthorized cross-policy lookups are blocked with structured `recovery_guidance` responses.

## Assumptions
- In local development and automated CI evaluation (`pytest`), `CLAIM_PULSE_DEPLOYMENT_MODE` defaults to `local` and `CLAIM_PULSE_STORAGE_BACKEND` defaults to `sqlite` so all tests pass deterministically with zero external GCP credentials.
- In production (`CLAIM_PULSE_DEPLOYMENT_MODE=agent_runtime` and `CLAIM_PULSE_STORAGE_BACKEND=firestore`), Terraform provisions Firestore (`(default)` database) and deploys all 4 agents to Vertex AI Agent Runtime (`us-central1`), where the Supervisor dynamically discovers the 3 specialists via their GCP labels (`app=claimpulse,role=specialist`).
